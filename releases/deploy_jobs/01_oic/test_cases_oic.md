### หมวดที่ 1: การตรวจสอบข้อมูลผู้เอาประกันและรถยนต์ (Data Compliance)

#### 🔹 TC-01: ตรวจสอบเลขบัตรประชาชน (Citizen ID Compliance)
* **วัตถุประสงค์:** ป้องกันข้อมูลเกินขนาด Schema `character varying(13)`
* **ขั้นตอนการทดสอบ:** กรอกเลขบัตรประชาชนมีเว้นวรรค หรือความยาวเกิน 13 หลัก แล้วส่งฟอร์มซื้อ พ.ร.บ.
* **สิ่งที่คาดหวัง:** ระบบตัดช่องว่าง (Trim) และจำกัดความยาวสูงสุด 13 หลักพอดี
* **ผลการทดสอบ:** ✅ **ผ่าน** — บันทึกลงตาราง Lead ได้สำเร็จ ไม่เกิด Column Overflow

#### 🔹 TC-02: ตรวจสอบรูปแบบป้ายทะเบียนรถยนต์ คปภ. (License Plate Regex)
* **วัตถุประสงค์:** ตรวจสอบป้ายทะเบียนให้ถูกต้องตามระเบียบ คปภ.
* **ขั้นตอนการทดสอบ:** 
  1. ทดสอบป้ายมีขีดหรือเว้นวรรค เช่น `1กข-1234`
  2. ทดสอบป้ายไม่มีพยัญชนะไทย เช่น `1234`
  3. ทดสอบป้ายมาตรฐาน เช่น `1กข1234`, `กข1234`
* **สิ่งที่คาดหวัง:** ป้ายผิดระเบียบต้องแจ้งเตือนทันที ป้ายถูกต้องตามเกณฑ์ คปภ. ต้องผ่านฉลุย
* **ผลการทดสอบ:** ✅ **ผ่าน** — Regex `/^(?=.*[ก-ฮ])([0-9]{1,2})?[ก-๙]+[0-9]{1,4}$/` ตรวจจับถูกต้อง 100%

#### 🔹 TC-03: จำกัดความยาวชื่อ-นามสกุล (Insured Name Boundary)
* **วัตถุประสงค์:** ป้องกัน Error ขนาดคอลัมน์ชื่อผู้เอาประกัน
* **ขั้นตอนการทดสอบ:** ส่งชื่อและนามสกุลยาวเกิน 120 ตัวอักษร
* **สิ่งที่คาดหวัง:** ระบบ Substring เหลือไม่เกิน 120 ตัวอักษรตามขนาดฟิลด์ใน DB
* **ผลการทดสอบ:** ✅ **ผ่าน** — ข้อมูลถูกบันทึกสำเร็จ ไม่ Error

#### 🔹 TC-04: จำกัดความยาวรุ่นรถยนต์ (Model Field Boundary)
* **วัตถุประสงค์:** ควบคุมขนาดฟิลด์ให้ตรงตามตารางมาตรฐาน คปภ.
* **ขั้นตอนการทดสอบ:** ส่งรุ่นรถยนต์ (`Model`) ยาวเกิน 65 ตัวอักษร
* **สิ่งที่คาดหวัง:** ระบบ Substring ความยาวไม่เกิน 65 ตัวอักษร
* **ผลการทดสอบ:** ✅ **ผ่าน** — บันทึกลง Database ได้พอดี

#### 🔹 TC-05: จัดการกรณีไม่ระบุวันเกิด (Birth Date Null Fallback)
* **วัตถุประสงค์:** ป้องกัน PostgreSQL Crash เมื่อได้รับ String ว่าง `""`
* **ขั้นตอนการทดสอบ:** ซื้อ พ.ร.บ. โดยปล่อยว่างช่องวันเกิด
* **สิ่งที่คาดหวัง:** API แปลงจาก `""` เป็น `NULL` ก่อนบันทึกลง Database
* **ผลการทดสอบ:** ✅ **ผ่าน** — บันทึกสำเร็จ ไม่เกิด 500 Internal Server Error

#### 🔹 TC-06: จำกัดความยาวรหัสพันธมิตร (Partner Code Constraint)
* **วัตถุประสงค์:** ควบคุมขนาดฟิลด์รหัสคู่ค้า
* **ขั้นตอนการทดสอบ:** ส่งรหัสพันธมิตรยาวเกิน 10 ตัวอักษร
* **สิ่งที่คาดหวัง:** จำกัดความยาวสูงสุด 10 ตัวอักษร
* **ผลการทดสอบ:** ✅ **ผ่าน** — ข้อมูลตรงตาม Schema

#### 🔹 TC-07: คำนวณเบี้ยตามพิกัดอัตรา คปภ. (Act Premium Calculation)
* **วัตถุประสงค์:** ตรวจสอบความถูกต้องของเบี้ยและภาษีตามประกาศ คปภ.
* **ขั้นตอนการทดสอบ:** ยิงเรียก API `/api/v1/premium/actAPI` สำหรับรถเก๋ง (รหัส 1.10)

  * เบี้ยสุทธิ (Net Premium): **464.40 บาท**

  * เบี้ยรวมทั้งสิ้น (Total): **499.05 บาท**
* **ผลการทดสอบ:** ✅ **ผ่าน** — ตัวเลขคำนวณถูกต้องตรงตามประกาศ คปภ. 100%

### หมวดที่ 3: การออกเลขกรมธรรม์และการรองรับ Concurrency (Policy Issuance)

#### 🔹 TC-08: การออกเลขกรมธรรม์ พ.ร.บ. หมวด MC (Policy No. Generation)
* **วัตถุประสงค์:** ออกเลขกรมธรรม์ พ.ร.บ. ผ่าน Stored Procedure `fn_lead_to_car_act`
* **ขั้นตอนการทดสอบ:** เรียก Execute ฟังก์ชันด้วย Lead No ที่ชำระเงินสำเร็จ
* **สิ่งที่คาดหวัง:** ได้เลขกรมธรรม์หมวด `MC` ถูกต้อง และสร้าง Record ใน `Policy_Car_Act`
* **ผลการทดสอบ:** ✅ **ผ่าน** — ออกเลขกรมธรรม์สมบูรณ์ครบถ้วนทุกฟิลด์

#### 🔹 TC-09: ป้องกันเลขชนกันเมื่อทำรายการพร้อมกัน (High-Concurrency Safe)
* **วัตถุประสงค์:** พิสูจน์ว่า `pg_advisory_xact_lock` ป้องกันปัญหาเลขซ้ำได้ 100%
* **ขั้นตอนการทดสอบ:** ใช้ Go Load Test ยิงออกเลขกรมธรรม์พร้อมกัน 20, 50 และ 100 Threads ในเสี้ยววินาทีเดียวกัน
* **สิ่งที่คาดหวัง:**
  * ไม่มี Error `duplicate key value violates unique constraint "MC_NO"`
  * อัตราความสำเร็จ **100%**
* **ผลการทดสอบ:** ✅ **ผ่าน** — อัตราสำเร็จ 100% (ความเร็ว ~27 ฉบับ/วินาที) ไม่มีเลขซ้ำ
